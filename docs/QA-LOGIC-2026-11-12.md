## 🚩 Flags for QA after TestFlight

Not fixed now. Check these on real devices once the TestFlight build is out, then decide whether to fix.

Context: no SwiftData or Core Data. Every Repo keeps JSON files (all written `.atomic`). Swift 6.0 strict mode,
with no `@unchecked Sendable`, `nonisolated(unsafe)`, `@preconcurrency`, `DispatchQueue` or `Task.detached`.

### Persistence (JSON files)
- [ ] **P-1** No schema version or migration
  - A file that won't decode is treated as empty and then overwritten (see L-2, A-6).
  - Only `ReadingSettings` and `BookState` have their own `init(from:)` for missing fields.
  - Idea: a `version` field per file, and rename an undecodable file to `.bak` instead of overwriting it.
  - QA: install the previous TestFlight build, add books, rate, read; update to the new build; check that nothing is gone.
- [ ] **P-2** No cross-file cleanup
  - Removing a book leaves its progress file, `Underlines/<fingerprint>/` and `LibVM.covers[id]` behind.
  - QA: remove a book, re-import it; check that progress and underlines behave as expected.
- [ ] **P-3** `struct` Repos have no write queue
  - `LibRepo`, `ReadingSettingsRepo`, `BookStateRepo`, `PendingImportRepo` and `LibraryIndexRepo` read, change and write without serializing (see L-6, R-7).
  - The `actor` Repos (`ProgRepo`, `RatingRepo`, `UnderlineRepo`, `BookContentRepo`) are fine.
  - QA: drag the text-size slider fast and reopen the book; remove a book while a shared book imports.

### Concurrency
- [ ] **CC-1** Actor reentrancy: state read before an `await` and used after it
  - `ReaderCtrl.currentPage` reads `position`, then awaits `paginate` (R-4).
  - `UnderlineRepo` checks `bookTask == nil` before `await modelEngine()` (A-8).
  - `ReaderStateCtrl.save` awaits a `struct` repo, so writes can land out of order.
  - QA (iPad): rotate during a late chapter of a long book and swipe at once.
- [ ] **CC-2** Fire-and-forget `Task {}` in VMs
  - `ReaderVM` 10, `LibVM` 9, `ReferenceVM` 6. Not kept, not cancelled, not ordered (R-6, R-7).
  - Idea: keep one `Task` per kind of action and `cancel()` the previous one.
  - QA: on a fresh open of a long book, tap a late chapter in Contents, then quickly an early one.
- [ ] **CC-3** Voice search may crash under Swift 6 isolation checks
  - `App/Library/Svc/SpeechSearchSvc.swift` is `@MainActor`. The `installTap` block (audio thread) and the
    `requestAuthorization`, `requestRecordPermission` and `recognitionTask` callbacks (background queues) may be
    inferred as MainActor-isolated and trap with `dispatch_assert_queue`. Not verified: the iOS 26 SDK may mark them `@Sendable`.
  - QA: on a real device, tap the mic in the Library; first launch (permission prompts), then speak, then stop.
- [ ] **CC-4** Risk if "Approachable Concurrency" (Swift 6.2) is turned on later
  - With `NonisolatedNonsendingByDefault` or default MainActor isolation, `async` funcs in `struct` Ctrl/Repo/Svc run on the
    caller's actor (MainActor): `LibCtrl`, `ImportCtrl`, `LibRepo.readEPUB`, `EPUBParseSvcEPUBKit.parse`.
  - EPUB parsing and file I/O would move to the main thread and freeze the UI during import.
  - If it's turned on: mark heavy work `@concurrent`, or make those types `actor`.
- [ ] **CC-5** 3 `ImplicitStrongCapture` warnings at `App/Library/VM/LibVM.swift:196-202`
  - `[weak self]` in the inner closures does nothing, as the outer `Task` holds `self` strongly. Harmless (`LibVM` lives for the app's lifetime).
