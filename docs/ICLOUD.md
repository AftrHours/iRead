# iCloud and ratings

One iCloud container, `iCloud.com.aftrhours.reader`, on team X7WUH4Z65U, holds two things:

| What | Database | Record type | Who can see it |
| --- | --- | --- | --- |
| Saved underlines, one record per finished chapter | Each reader's **private** database | `ChapterUnderlines` | Only that reader. It counts against their iCloud storage (a few KB a chapter). |
| Thumbs up / down on reference passages, once the reader agrees to share | The **public** database | `UnderlineRating` | The developers, in the CloudKit Console |

The code is in `App/Analysis/Svc/CloudSvc.swift`, `Repo/UnderlineRepo.swift` and `Repo/RatingRepo.swift`. The entitlements come
from `project.yml` (`App/iRead.entitlements` is generated by `xcodegen generate`).

## One-time setup

1. **Create the container.** Open `iRead.xcodeproj` in Xcode → iRead target → Signing & Capabilities. The team should be
   "Shanon Giuly Istanto" and the iCloud section should list `iCloud.com.aftrhours.reader` with CloudKit ticked.
   If the container is shown in red, click the refresh button under Containers so Xcode creates it on the team.
   If Xcode changes anything else in the project, run `xcodegen generate` again: `project.yml` is the source.
2. **Sign in on the device** (Simulator or real): Settings → Sign in, with any Apple Account.
   Without an account the app still works, but nothing goes to iCloud.
3. **Open a book and rate one reference.** In the Development environment, CloudKit creates both record types on the first save.
4. **Set up the record types** at [icloud.developer.apple.com](https://icloud.developer.apple.com) → CloudKit Database →
   `iCloud.com.aftrhours.reader` → Development:
   - Indexes → `UnderlineRating` and `ChapterUnderlines` → add a **Queryable** index on `recordName`, so the Console can list them.
   - Security Roles → `UnderlineRating` → take **Read** away from **World**, so readers can't read each other's ratings.
5. **Before TestFlight or the App Store:** Deploy Schema Changes to Production. TestFlight and App Store builds use the
   Production environment; builds run from Xcode use Development. The data in the two is separate.

## Checking that it works

- **Reader menu** (any build): the last row says iCloud On, Off, Not Allowed or Not Reachable. Off means: sign in in the
  Settings app, then come back to the app; the row updates.
- **Debug sheet** (debug builds: the ladybug button, or ⌘⇧D), section iCloud:
  - Account: signed in or not.
  - This chapter: "Loaded from iCloud", "Underlined here and saved to iCloud", "Saved on this device, so iCloud wasn't asked",
    or the error iCloud gave.
  - Ratings: whether sharing is on, how many wait to be sent, and the last try.
- **Reinstall** (or a second device on the same Apple Account): open the same book. The chapter's line should say
  "Loaded from iCloud".
- **CloudKit Console**: the records themselves (below). Private records only show with "Act as iCloud account", signed in as the
  same Apple Account.

**Records don't show in the Console?**
- Check the environment switch at the top of the Console. Builds run from Xcode (simulator or a real device) write to
  **Development**; only TestFlight and App Store builds write to **Production**, which stays empty until then.
- Record types appear under Schema → Record Types only after the first save in that environment.
- In Records, pick **Public Database**, zone `_defaultZone`, then **Query Records** to get the record type list. Saved underlines are in the **Private Database**, which only shows after
  "Act as iCloud account" with the same Apple Account as the device.
- If querying fails with "not marked queryable", add the `recordName` index (setup step 4).

## Reading the ratings

CloudKit Console → Records → Public Database → `_defaultZone` → Query Records → `UnderlineRating`. Each record has:

| Field | Meaning |
| --- | --- |
| `verdict` | `up` or `down` |
| `phrase`, `kind` | The underlined phrase and its UnderlineKind |
| `sentence`, `sentenceText` | The underlined sentence: its number, counted from the chapter's first sentence (0), and its text |
| `reference`, `referenceText` | The passage shown as the reference: its sentence number (same counting) and its text |
| `decidedBy` | `model` or `rules` |
| `bookTitle`, `book`, `chapterIndex` | The book (`book` is its text fingerprint) and the chapter (0 = first) |
| `engineVersion`, `appVersion` | `UnderlineRepoKnobs.engineVersion` and the app's version |

To get them all as JSON, use `cktool` (comes with Xcode). Make a user token in the CloudKit Console first, then:

```sh
xcrun cktool save-token --type user
xcrun cktool query-records --team-id X7WUH4Z65U --container-id iCloud.com.aftrhours.reader \
  --environment production --database-type public --record-type UnderlineRating > ratings.json
```

(`xcrun cktool query-records --help` lists the options if they change.)

**Turning a rating into a golden set item** (`Dataset/underline-gold.json` in UnderlineEngine): `phrase`, `kind`,
`sentence` → `sentence.index`, `sentenceText` → `sentence.text`. A thumbs up means `expected` is
`{ "kind": "underline", "references": [reference] }`. A thumbs down only says this reference is wrong, so a person still
decides the right references, or `none` with a reason. The app splits sentences with its own parser, so check the numbers
against the golden set's text before mixing the two.

## Privacy

The first rating asks whether to share. Saying no sends nothing, and the Share Ratings switch in the reader menu changes the answer.
A shared rating holds a sentence and a passage of the book, without the reader's name. CloudKit links each record to a random ID
that is different for each app, not to the reader's Apple Account. In App Store Connect's privacy section this is
"Other User Content", not linked to the user.
